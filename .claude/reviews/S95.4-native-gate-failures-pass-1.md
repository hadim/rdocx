## D1. Missing result insertion breaks the source run QName

**Classification:** Product correctness and XML preservation defect. Must fix before acceptance.

`write_missing_legacy_result_region` closes the surrounding source run using hardcoded `w:r`, then opens canonical `w:r` for the separator, result and resumed end-marker run (`crates/rdocx-oxml/src/text.rs:11510`, `crates/rdocx-oxml/src/text.rs:11516`, `crates/rdocx-oxml/src/text.rs:11525`). The source rewriter previously retained the actual opening element and records no canonical replacement end name for that run (`crates/rdocx-oxml/src/text.rs:13081`). At the original closing event, it consequently emits the original end QName (`crates/rdocx-oxml/src/text.rs:13212`). A source `<r>...</r>` therefore gets an intervening `</w:r>`, and the reopened canonical run can later meet the original `</r>`. Expanded namespace equality does not make those different lexical start and end names well-formed XML.

Both reported fixtures are valid Word XML. One declares the default Word namespace on each run (`crates/rdocx-oxml/src/text.rs:20010`). The other inherits it from the paragraph (`crates/rdocx-oxml/src/text.rs:20048`). Both are accepted before mutation and fail reparsing the serialized output at `crates/rdocx-oxml/src/text.rs:20035` and `crates/rdocx-oxml/src/text.rs:20077`. The actual OXML log reports `MismatchedEndTag { expected: "r", found: "w:r" }` for both.

This is shared behavior, not a fixture-specific parser problem. Both the Start and Empty end-marker branches call the helper (`crates/rdocx-oxml/src/text.rs:12968`, `crates/rdocx-oxml/src/text.rs:13111`). Main parsed-field serialization and nested parsed-field source rewriting use `update_complex_field_source` (`crates/rdocx-oxml/src/text.rs:10894`, `crates/rdocx-oxml/src/text.rs:12054`). Current-value assignment can request publication of an absent result region (`crates/rdocx-oxml/src/text.rs:2059`). Rust document filling reaches this setter through its source-order field traversal (`crates/rdocx/src/field.rs:906`, `crates/rdocx/src/field.rs:2204`, `crates/rdocx-oxml/src/text.rs:1671`). Python document filling calls the native document setter (`crates/rdocx-py/src/document.rs:12816`). Downstream validation can turn malformed candidate bytes into refusal of an otherwise valid update. This review does not claim every facade path publishes malformed bytes.

**Remediation:** Preserve or deliberately replace the actual enclosing run QName as a matched pair, including the resumed run's closing event. Keep inserted canonical names bound to the Word namespace under inherited default namespaces, alternate Word prefixes and shadowed `w`. The helper currently ignores its binding flag for run starts (`crates/rdocx-oxml/src/text.rs:11515`), so repairing only the first close tag is insufficient. Retain both existing valid fixtures. Add focused controls for absent result publication with Start and Empty end markers and alternate source prefixes, including nested source rewriting where applicable. Assert well-formed output, correct current value, unchanged reset default and retained foreign data. Do not change the valid input fixtures to canonical `w:r` to conceal this defect.

Actual work of three children is consistent with rewriting the three field, tab and bookmark entries while retaining proved ordinary neighbors. **Remediation:** Make this phase a genuine whole-writer control using the existing `CanonicalBlockProofOff` guard, which prevents offering either record (`crates/rdocx/src/document.rs:6718`, `crates/rdocx/src/document.rs:6729`), or explicitly remove every relevant writer record. Preserve the assertion requiring all body children in that whole path. Preserve the earlier four-child changed-neighbor assertion. Do not weaken the full-write expected count to three.

## D3. Scalar scan assertion treats cold qualification as warm lookup

Physical table-cell correspondence performs one more scan (`crates/rdocx/src/document.rs:12503`). Those four real calls explain the reported four, with no need to posit a new per-cell scan loop.

`uncounted_scan` pauses only `MAIN_BODY_BLOCK_SCANS`, not `STORY_OWNER_SCANS` (`crates/rdocx/src/document.rs:7627`). The actual owner scanner charges each invocation (`crates/rdocx/src/document.rs:15602`). **Remediation:** Assert cold qualification explicitly, then reset counters and repeat the stable scalar lookup to prove the intended warm two-scan bound. Retain the independent one-source-build, one-table-visit, bounded prefix work and cell-visit assertions. ## D4. Two form tests still require overwriting reset defaults

**Classification:** Stale semantic assertions contradicting the approved F-288 contract.

The contract says current-value assignment never rewrites the reset default (`.claude/plans/F-288-design.md:68`). The implementation states and implements that split (`crates/rdocx-oxml/src/text.rs:2047`, `crates/rdocx-oxml/src/text.rs:2059`). Text-only current changes deliberately bypass the legacy metadata rewriter (`crates/rdocx-oxml/src/text.rs:10879`, `crates/rdocx-oxml/src/text.rs:10886`).

`legacy_form_rewriter_targets_only_direct_ffdata_owner` nevertheless expects the real owner's default to become `new` (`crates/rdocx-oxml/src/text.rs:20674`). The recorded output instead preserves both the producer decoy and the actual `old` default and inserts cached result text `new`. `empty_text_input_form_can_be_expanded_for_value_mutation` expects assignment to invent a reset default (`crates/rdocx-oxml/src/text.rs:20725`). Its recorded output correctly preserves the empty `textInput` metadata and changes the existing result text to `new`. Neither log demonstrates a product defect in current/default separation.

**Remediation:** Assert current value and saved/reparsed display `new`, with explicit old reset default preserved in the first case and absent reset metadata preserved in the second. Keep the foreign decoy byte-preservation assertion. Preserve the direct-owner rewrite test's original purpose in a checkbox or dropdown current-metadata edit that actually invokes the metadata rewriter, rather than allowing a text-only cache change to stand as proof of metadata owner targeting. Do not change production code to restore the obsolete default-overwrite behavior.
