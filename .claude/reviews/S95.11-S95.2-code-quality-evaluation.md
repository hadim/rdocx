## Should-fix

### S1, rendered STYLEREF relative numbers disagree with field evaluation

`crates/rdocx-layout/src/engine.rs:8214`
`crates/rdocx/src/field.rs:14379`

For an unnumbered caller referencing a level-three heading, the evaluator passes the target's own numbering as the comparison context when the caller has no numbering. The renderer passes None. The shared formatter therefore receives different inputs and produces different text for the same field.

Reproduction: create three headings in one numbering instance with level texts `Chapter %1.`, `Section %2.` and `Clause %3.`. Add four ordinary, unnumbered paragraphs containing STYLEREF fields for Heading 3. The current-source executable probe observed:

| Switch | Field evaluation | Rendered positioned field text |
|---|---|---|
| `\n` | `Clause 1` | `Clause 1` |
| `\r` | `Clause 1` | `1.1.Clause 1` |
| `\r \t` | `1` | `1.1.1` |
| `\w` | `Chapter 1.Section 1.Clause 1` | `Chapter 1.Section 1.Clause 1` |

The discrepancy remains after update_fields and after ordinary save/reopen. This is an actual deterministic rendering inconsistency, not merely different stored stale caches. The committed mode test at `crates/rdocx/tests/regression_test.rs:405157` asserts evaluator results but never asserts the rendered field text. The page-placement fixture at line 404368 uses one numbering level, which cannot distinguish relative from full context.

Fix the semantic context consistently across both consumers, preferably through one concrete policy helper if their existing ownership boundary permits it. Regression coverage must compare evaluation, updated caches and actual positioned output for multilevel `\r` and `\r \t`, with `\n` and `\w` controls. This audit establishes internal inconsistency against the implemented evaluator contract and existing expected results. It does not claim a new native Word oracle observation.

### S2, grammar 1 rejects empty arrays for a supported implicit loop scope

`crates/rdocx/src/template.rs:405`
`crates/rdocx/src/template.rs:500`
`crates/rdocx/src/template.rs:1664`

The versioned evaluator supports unqualified lookup in the current loop item, so `{{name}}` resolves a person's name inside a person loop. When the array is empty, preflight installs a deferred null item. deferred_expression only recognizes the explicit variable name, such as person in `person.name`. It does not defer the supported implicit name lookup. expression_value consequently searches the root and returns a missing-path error.

Reproduction uses three sibling paragraphs:

```text
{% for person in people %}
{{name}}
{% endfor %}
```

| Payload and expression | Legacy grammar | Grammar 1 |
|---|---|---|
| people contains one object with name Ada, implicit name | Ok(1), emits Ada | Ok(1), emits Ada |
| people is empty, implicit name | Ok(0) | Error, missing template path |
| people is empty, explicit person.name | Ok(0) | Ok(0) |

An otherwise valid report therefore fails only when its collection has no rows under grammar 1. The refusal remains atomic, which the probe separately asserted. The design retains lexical scopes at `.claude/plans/F-284-design.md:51`. The existing empty-loop test at `crates/rdocx/src/document.rs:51702` exercises the legacy entry and an explicitly qualified variable, missing this combination.

Unify deferred lexical resolution without weakening validation of genuinely missing root properties, wrong intermediate containers or malformed body syntax. Cover empty and nonempty collections for both implicit and explicit scope paths in each grammar.

## Follow-up execution and pattern assessment

The follow-up used the same HEAD and changed no implementation. A fresh `cargo build -p rdocx --lib` supplied the actual native library. Cargo's JSON compiler-artifact records selected matching dependency libraries for an independent Rust probe, compiled from stdin into a disposable temporary directory. The probe inspected positioned text carrying field_source, not generic paragraph text or PDF text extraction.

An exploratory run established the switch matrix above before and after update_fields and save/reopen. A separate five-test assertion run produced 3 passes and 2 failures, with process exit 101. The failing tests were styleref_r_render_agrees_with_evaluation and implicit_loop_scope_accepts_empty_array_in_grammar_one. Their failures exactly match S1 and S2. The passing controls established `\n` and `\w` consistency across update/reopen, legacy/explicit-empty/populated-implicit loop behavior, Unicode filters, literal inserted delimiter text and byte-identical rollback after the second formatter callback fails. The existing `cargo test -p rdocx-layout --lib style_resolver::tests::` also passed all 33 selected tests. These passes do not cancel the independently reproduced failures.

The strongest recurring behavior is careful local invariant handling. PowerPoint frontier custody, template late-error rollback, nonrecursive inserted data and the shared numbering counter all held in the inspected cases. No second counter, dependency engine or speculative dependency was needed for these features.

The weakest recurring behavior is proving consistency across boundaries. S1 shares the formatter but duplicates caller-context policy. S2 implements implicit scopes and empty-loop preflight separately without testing their composition. B1 checks policy before completion, then changes the very metadata that policy reads. In all three cases, individual pieces can pass their existing checks while their combination fails. This pattern is supported by three concrete findings, not by a general assumption about Grok.

Test quantity is stronger than test discrimination here. The committed STYLEREF fixture distinguishes the modes in evaluation, while the rendering fixture uses one level where the same modes collapse to the same answer. See `crates/rdocx/tests/regression_test.rs:405157` and `crates/rdocx/tests/regression_test.rs:404368`. Empty-loop coverage uses the explicit lexical spelling while implicit lookup has a separate working path. See `crates/rdocx/src/document.rs:51702` and `crates/rdocx/src/template.rs:1664`. More repetitions of these fixtures would not expose S1 or S2.
