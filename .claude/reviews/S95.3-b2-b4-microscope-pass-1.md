## Defects

### B2, transparent payload validation still ignores reference events

`crates/rdocx/src/content_control.rs:2977`
`crates/rdocx/src/content_control.rs:2980`
`crates/rdocx/src/content_control.rs:2951`

The new text guard rejects nonspace Text and CData events, but ignores GeneralRef events. The element index also excludes these events. Consequently a nested control whose `sdtContent` contains only `&#65;` or `&lt;` is treated as an empty payload and passes the inherited inline grammar. These references represent nonspace character data, which is illegal directly inside inline `sdtContent`. They are not runs or empty content.

Independently reproduced with the authenticated current extension, using fresh documents for each operation. The body had a host paragraph and a second paragraph containing an outer control tagged `outer`, id 1, whose content was another control, id 2. That inner control's content was exactly `&#65;`, then separately `&lt;`. For each input, cloning or moving the outer control into the host paragraph and unwrapping the outer control all succeeded. All six operations changed serialized package bytes, and the reference remained in `word/document.xml`.

The original nested row cases are repaired, but the same destination invariant still fails on reference-only content. Retain B2. Account for reference events when deciding whether payload is empty or contains illegal text. Add discriminating move, clone and unwrap refusals with unchanged bytes and the existing placement or unwrap error substrings. Preserve genuinely empty content.

### B4, reference syntax and root boundaries still admit malformed stores

`crates/rdocx/src/content_control.rs:1968`
`crates/rdocx/src/content_control.rs:1878`
`crates/rdocx/src/content_control.rs:1432`

Attribute character-reference validation explicitly accepts uppercase `X` as the hexadecimal introducer. XML 1.0 permits lowercase `x` only. Also, GeneralRef validation does not check depth, unlike the neighboring Text path. A recognized reference before or after the root therefore bypasses the one-element boundary check. XML document grammar permits whitespace, comments and processing instructions around the root, not character or entity references. These rules follow [XML 1.0 productions 66, 1, 22 and 27](https://www.w3.org/TR/xml/).

Independently reproduced on fresh documents with the authenticated current extension:

- `<root a="&#X41;"/>` returned a store id and retained the invalid attribute syntax verbatim.
- `&#65;<root/>` returned a store id and retained the reference before the root verbatim.
- `<root/>&lt;` returned a store id and retained the reference after the root verbatim.

Each returned `{00000000-0000-4000-8000-000000000000}`, changed package bytes, and stored exactly the supplied bytes in `customXml/item1.xml`. These are successful publications, not error-text discrepancies. The original six malformed inputs are repaired, but well-formed-element admission remains incomplete. Retain B4. Reject these inputs before `stage_custom_xml_store`, keeping `not XML` in the refusal and leaving package bytes unchanged. Preserve lowercase hexadecimal references, decimal references, predefined entities and colon-bearing XML Names without requiring namespace bindings.

## Caller and contract assessment

Their remaining reference-event hole is B2.

The recursion uses `child_allowed`, rather than a second element grammar. Within a nested Word `sdt`, only `sdtContent` children are traversed as payload. `sdtPr` and `sdtEndPr` are skipped as properties, and other direct element children cause false. Empty content remains allowed. Element grammar mismatch returns false and parser failures propagate as errors. The supplied regressions do not independently constrain every property, empty-content or malformed-input branch, so this source assessment is not a claim that those cases all ran.

**OOXML**: The detached wrapper declares the missing `xmlns:w`. Its prefix length is exactly the opening literal length plus the namespace URI byte length plus the closing quote and angle bracket. The selected range therefore points to the control itself. This fixes the observed detached `w:sdtContent` extraction failure. Direct block and unwrap extraction continue to parse the full document. Additional probes with document-level alternate Word prefix `x`, both throughout the shell and only on `sdtContent`, refused incompatible nested row move and clone with unchanged package bytes. No remaining detached element-extraction bypass was demonstrated. Reference-only fragments still skip effective payload validation as B2 describes. Validation does not rewrite property order or raw payload bytes.

Leaving `repeating_content` unchanged is sound for this remediation. It is a one-level repeating-section admission check, not a move, clone or unwrap publisher. Its role does not replace any of the publication guards traced above.

Store admission now checks Start and Empty element names, successful attribute names and raw attribute values before staging. XML Name rules allow colons, including multiple colons. Literal less-than signs refuse, and predefined and numeric reference expansions are checked without reserializing valid bytes. GeneralRef events now reach validation, but their context remains unchecked under B4. Bibliography still calls the allocator directly and stays off public store admission. `validate_strict_xml_1_0` was not substituted, preserving the supported unbound-prefix contract.

**Atomic refusal**: The new refusal paths still hold atomicity. Direct block guards precede delegation. Nested edits and unwrap mutate staged candidates only, and store admission precedes candidate allocation. The new Rust and Python refusal assertions compare complete serialized package bytes and require `does not match`, `parent cannot hold` or `not XML` as appropriate. The failures above are missed refusals, not partial mutations after an error. Additional store probes confirmed `<root a:b:c="1"/>` and `<root a="&#60;"/>` remain accepted verbatim. Literal U+0001 probes refused later during package validation with unchanged bytes, which is not proof of complete pre-staging admission.
