## Minimal implementation recommendation

Use existing files, concrete parsers, inventories and prepared revision types. No new framework, trait, generic, crate, module, file, public API or owner history is needed. Add only private concrete proof data next to the existing XML publisher. A small private verdict such as exact no-op, proved stable ordinary shape, proved unchanged-payload frame, or stage makes the pre-native choice explicit. The local proof must carry both topology and evidence of a real modeled change. A topology proof alone cannot decide whether scopes should retire.

### Local-versus-staged decision

1. Validate origin, captured scopes, requested physical kind and current route first, as `checked_path` already does (`presentation.rs:2184`). Read the current selected snapshot. Exact `before_xml == submitted_bytes` returns before preparation, parsing or cloning. This covers the original benchmark no-op without weakening owner checks.
2. For ordinary Shape, parse both selected snapshot and submitted bytes with `rpptx_oxml::shape_tree::CT_Shape`. For frames use `CT_GraphicFrame`. These are bounded, concrete projections of one owner. Native assignment uses precisely these parsers (`crates/rpptx/src/lib.rs:6272`). A parse failure or an inability to establish context means stage, not a new binding-level final rejection.
3. Compare projected old topology with actual native topology, then projected incoming topology with that same topology. Require equal `Option<u32>` identity, actual kind, table flag and an explicit optional text-body signature. Use `Option<Vec<usize>>`, where `None` means no body and `Some([])` means a body with zero paragraphs. The current tuple loses that distinction (`presentation.rs:3982`), while owner inventory creates a body owner whenever a frame exists (`presentation.rs:2736`).
4. Each vector entry counts only `TextRun::Run`, matching native `TextParagraphRef::run_count` (`crates/rpptx/src/lib.rs:24356`). Neither `paragraph.runs.len()` nor all XML children is correct. If naming `TextRun` needs `oxml-drawing`, add the existing workspace dependency to rpptx-py for this specific parser-proof consumer. Do not add a public run-count accessor or re-export to avoid that dependency. CT_Shape already exposes `text_body` (`crates/rpptx-oxml/src/shape_tree.rs:707`).
5. A frame proof requires unchanged complete `graphic_data`, not only table presence or row/column counts. Include retained payload metadata in that comparison, with the same namespace context, or decline local proof. The typed frame exposes `graphic_data` and has concrete equality (`crates/rpptx-oxml/src/graphic_frame.rs:132`). This preserves bounded table/chart/opaque-frame name and transform changes without admitting changed cell bodies through an empty shape-level text signature. Prepare the affected table/grid/cell/body/text successors according to the existing Shape-XML policy. Do not apply ordinary shape retirement to only the frame header.
6. Require a pre-native witness that a modeled scalar actually changes. For the minimal repair, decoded nonvisual name/accessibility values and concrete geometry fields supply such witnesses. Stable ordinary text scalar edits can use changed regular-run text with unchanged body/paragraph/run topology. Compare native old values with parsed old and incoming values before mutation. A changed typed scalar that native serializes is evidence of real change. A byte difference, parser-object inequality from raw metadata, or a count match alone is not. Semantic equality, prefix-only changes, opaque-only differences and any unproved witness go through staged admission, where before/after comparison is safe. Never return a typed-equality no-op before native validation of the submitted raw bytes.
7. For a proved local real change, prepare all affected owners/scopes and index capacity before invoking the existing native replacement with the original submitted string. On native error, discard preparation. On success, commit the prepared local update with no further serializer, parser, structural proof or fallback. The witness must make native success imply actual modeled change. If that implication cannot be established for a case, stage it. Do not retain the current post-native `read_xml` just to recover a change bit.
8. For every staged case, clone the candidate only on that branch. Dispatch the same native operation against it, perform all post-native XML/structure reads there, enforce table-presence refusal there, return on actual no-op, construct survivors and candidate inventory, prepare scopes and complete indexes, then publish with `publish_owners`. Any failure drops the candidate. Broad work remains permissible for these unproved/structural cases, not for ordinary supported scalar witnesses.

This restricted witness design avoids a new native public outcome API. It deliberately trades local optimization of unproved XML spellings for the existing staged correctness boundary. It must cover ordinary changed name/geometry XML as well as exact no-op XML. If implementation discovers that a proposed witness does not survive native projection, narrow that witness and retain staged admission. Do not solve the uncertainty with an unconditional presentation clone or a guessed no-op classification.

### Native authority and input contracts

The local proof only establishes binding publication shape and change status. It never admits XML. Native `check_ppt_xml_input`, relationship facts, submitted raw frontier checks, inherited MC checks, signature handling, identity and projected-model validation remain mandatory (`crates/rpptx/src/lib.rs:6093`, `crates/rpptx/src/lib.rs:6099`, `crates/rpptx/src/lib.rs:6175`, `crates/rpptx/src/lib.rs:6185`). Always pass the original input, not reserialized proof XML. Otherwise a parser may erase the foreign geometry or opaque bytes that admission must inspect.

Any standalone proof-parser failure defers to staged native admission, particularly ancestor MC authority, inherited namespace requirements and prefix-sensitive retained raw content. Preserve valid alternate QName prefixes and same-root namespace declarations. Do not strip prefixes, search for a literal `<a:tbl>`, count descendant tags, infer table payload from a table-looking opaque subtree or decode a URI twice. Shape ID equality is `Option<u32>` equality, not a defaulted zero, and native still refuses identity changes (`crates/rpptx/src/lib.rs:6295`). CT_Shape reads namespace-resolved roots and checks writer-prefix conflicts (`crates/rpptx-oxml/src/shape_tree.rs:1445`).

For graphic-frame table-presence preflight, a successfully proved transition can retain the existing early named refusal. If detached parsing cannot prove presence, run native admission on the candidate, then compare actual old/new presence before publishing. Do not turn proof-parser uncertainty into refusal of valid contextual input. Native rejection remains atomic. Both table-to-opaque and opaque-to-table keep the existing unsupported contract.

Retain structural missing/duplicate-ID refusal in `finish_prepare_owners` (`presentation.rs:3434`). The duplicate-ID topology reproduction should still refuse, now before any live state changes. Stable scalar proof does not require a whole-package duplicate scan because it neither moves identities nor changes inventory topology. Do not broaden that local exemption to a structural edit. Root append keeps its existing target-slide preflight rather than acquiring general package-wide refusal.

### Scalar and fill preparation sequence

Replace the combined late `publish_local_property` operation with private prepare and commit phases using existing `PreparedRevision`. The two real consumers are `PyShape::edit` and `write_fill`. Validate captures and conversions, resolve the actual owner, build arguments, classify actual no-op or real change, then prepare the revision. Only then call the atomic native setter. Commit the already prepared revision after success. Equal fill already has the required early return (`dml.rs:205`). Keep gradient token/cache changes after successful publication and ensure they cannot allocate or reject there (`dml.rs:492`).

For Shape callers, remove reliance on post-live XML serialization and XML reconstruction. Supply pre-native no-op/change evidence from the concrete setter input and actual stored state, including absent versus explicit values. Where the callback has no such proof, run it on the existing staged candidate, compare there, and prepare there. Alt text, name and ordinary non-connector geometry need the bounded proven path. Crop/style/preset/theme/connector callers cannot silently inherit an unproved classification. Native geometry and fill already own rollback or broader transaction selection (`crates/rpptx/src/lib.rs:40120`, `crates/rpptx/src/lib.rs:11367`). Do not replace them with detached setters that omit connector glue, materialization or relationship handling.

The exclusive mutable wrapper borrow must span preparation through native call and commit. No Python callback, capture allocation or scope mutation may intervene. `commit_scopes` checks origin/serial/generation/retirement before retiring anything and allocates nothing after those checks (`crates/oxml-py-support/src/lib.rs:484`). Under this private sequence, those checks are invariant checks, not a second admission stage. Do not use `expect` to hide a remaining externally reachable refusal after mutation.

### Inventory locality after root append

Root textbox append adds its three owners at the inventory end (`presentation.rs:3633`). Consequently a slide's owners are not necessarily contiguous. Never use a slide start/end interval as the local shape's descendant set.

No new descendant index is needed for this repair. Ordinary shape descendants can be enumerated from the proved optional body and regular-run vector, then resolved through existing body/path/generation indexes, as `prepare_simple_shape_xml` does (`presentation.rs:3838`). Appended root triples are contiguous within that shape, but indexed enumeration is clearer and does not depend on vector order. For unchanged graphicData, enumerate the actual selected table's rows/cells/bodies/paragraphs/regular runs and resolve those existing routes before mutation, bounded by the affected frame. Native inventory already defines those routes (`presentation.rs:2746`). Group additions and grid changes use whole replacement, which reconstructs traversal order. Do not add a second map merely to recover slide contiguity.

Preserve fully prepared `OwnerIndexes`, owned layout/master keys and pre-reserved generation successor capacity. Local commit may change generations at known indices, not allocate new path keys or scan all owners. Preserve selected shape/table/grid retirement policy and first-cause operation labels. Refusal assertions should compare actual index entries and scope states, not only cardinalities.

## Risks, evidence limits and handoff

The main implementation risk is claiming the scalar witness is stronger than it is. Stored defaults, inherited geometry, namespaces and parser projection can make equal effective values differ physically or make different submitted bytes serialize identically. Such uncertainty stages. A proof-parser success is not raw-XML admission. A proof-parser failure is not invalid-input evidence. The local branch must have no post-native fallible read, inventory discovery or fallback.

Native fallback may still perform broader work for signatures, relationships, connectors or contextual raw frontiers. This investigation promises bounded ordinary admitted scalar edits, not constant cost for arbitrary XML or complex structural changes. Checked allocation refusal must happen before live mutation. Unchecked process-wide allocator aborts are not demonstrated to be recoverable, and no allocator exhaustion was executed here. Do not claim universal OOM qualification from reserved hash-map capacity.
