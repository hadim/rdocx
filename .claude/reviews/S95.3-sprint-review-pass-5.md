The new destination guard correctly recognizes qualified repeating markers in the staged XML. The existing typed-property serializer can erase that qualification before the guard runs. Reading a supported repeating marker through another correctly bound prefix normalizes its element name to `w15:repeatingSection` or `w15:repeatingSectionItem`. `write_type` emits that name without establishing its namespace binding. Its captured namespace bindings are not applied there. A valid alias-bearing source consequently reaches admission with unbound canonical marker names. Qualified type detection then treats the nested controls as ordinary shells.

The discriminating input is a namespace-valid document with a host paragraph followed by ordinary block control `container`, id 4. It contains ordinary block control `outer`, id 1, which declares:

```xml
xmlns:rep="http://schemas.microsoft.com/office/word/2012/wordml"
```

Inside `outer` is section id 2 with `<rep:repeatingSection/>`, containing item id 3 with `<rep:repeatingSectionItem/>`. The item's content is the following empty, metadata-bearing block customXml wrapper:

```xml
<w:customXml w:uri="u" w:element="kept"><w:customXmlPr><w:attr w:name="x" w:val="kept"/></w:customXmlPr></w:customXml>
```

There is no `w15` declaration in the original input. Both markers are correctly qualified through `rep`. An independent namespace-aware parse of the exact original package XML succeeds and finds exactly one qualified section and one qualified item. The nested source deliberately takes actual paragraph insertion rather than direct-body boundary insertion.

On fresh imports, both public Python `move_content_control(outer, host_paragraph)` and `clone_content_control(outer, host_paragraph)` succeed. Saved XML places `outer` inside the host paragraph and contains canonical `<w15:repeatingSection/>` and `<w15:repeatingSectionItem/>`, with only the inherited `rep` binding retained. A namespace-aware parse of each saved result fails with `unbound prefix`. The original package was not saved or normalized by a reviewer `to_bytes` call before either mutation. Public location lookup and the actual operation are sufficient to encounter the fault.

As a paired control, change only that input prefix and declaration from `rep` to `w15`. Both operations now refuse with `content control placement does not match its parent`, retain namespace-valid output and leave `outer` outside the host paragraph. Earlier diagnostic probes also observed full-byte equality for these canonical-prefix refusals. This separates the serialization interaction from an unconditional empty-payload bypass.

This is an integrated interaction between existing typed parsing/writing and the new lifecycle guard.
