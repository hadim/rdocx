### B2, the placement guard accepts incompatible content through a nested control

`crates/rdocx/src/content_control.rs:2834`
`crates/rdocx/src/content_control.rs:2743`
`crates/rdocx/src/content_control.rs:2802`
`.claude/plans/F-285-design.md:40`

Both nested operations now call the guard before splice and publication, but the reused validator checks only immediate content children. It accepts `w:sdt` in every supported parent grammar without checking that nested control's content against the inherited slot. A valid table-owned row control containing another row control therefore passes the inline destination check. The outer content's immediate child is `w:sdt`, while its descendant `w:tr` is ignored at greater depth.

This was reproduced separately for Python `clone_content_control` and `move_content_control` using the identified current-source extension. The input body contained a host paragraph followed by a table. The table's outer control had id 1 and tag `outer-row`, and its content was a nested control with id 2 whose content was `<w:tr><w:tc><w:p/></w:tc></w:tr>`. The destination was the host paragraph's ContentLocation. Both calls succeeded, and serialized output placed the nested row payload inside that paragraph. Clone refreshed the ids to 3 and 4. Move retained 1 and 2. This is a placement violation, not merely a stale-location or identity problem.

Validate transparent nested control content under the actual destination grammar before publication. Add move and clone refusals for this nested row case, corresponding nested cell/inline mismatches, unchanged package bytes on refusal, and compatible nested controls as positive controls. The new direct row, cell and inline fixtures do not distinguish this remaining bypass. The same depth-limited helper also serves unwrap, so its consumers need consistent placement policy.

### B4, iterating attributes still does not establish XML well-formedness

`crates/rdocx/src/content_control.rs:1885`
`crates/rdocx/src/content_control.rs:1432`
`.claude/plans/F-287-design.md:31`

The new iterator rejects duplicate names and unquoted values, but it discards each successful Attribute without validating its name or value. quick-xml's attribute iterator finds quoting and separators. That alone does not reject a literal `<` inside a quoted attribute, invalid names, or undeclared entity references.

Using the identified extension, separate fresh documents accepted `<root a="<"/>`, `<root 1bad="x"/>` and `<root a="&bad;"/>`. Each call returned a store id, serialized successfully, and retained those exact bytes in `customXml/item1.xml`. The literal `<` case alone disproves the promised well-formed-element contract. In the same probe, duplicate and unquoted attributes correctly refused with unchanged package bytes.

Complete XML well-formedness validation before allocating or publishing the store, including attribute names and value syntax. Add discriminating refusals for these cases with unchanged package bytes. Preserve valid bytes verbatim. This finding does not request namespace-well-formedness enforcement or rejection of the explicitly retained `<root a:b="1"/>` case.
