### B4, declaration encoding is checked as a name but not against the supplied bytes

`crates/rdocx/src/content_control.rs:1834`
`crates/rdocx/src/content_control.rs:1949`
`crates/rdocx/src/content_control.rs:1957`
`crates/rdocx/src/content_control.rs:1432`
`crates/rdocx/src/content_control.rs:1446`
`.claude/plans/F-287-design.md:31`
`docs/hld/03-architecture.md:1840`

The contract requires one well-formed XML element and atomic refusal of bytes that are not XML. The validator interprets the whole input as UTF-8, but the declaration helper only verifies EncName syntax before marking encoding seen. It never checks whether the bytes satisfy that declared encoding. The byte API supplies no external transport encoding override. XML 1.0 section 4.3.3 requires an encoding mismatch to be reported as a fatal error. See the [W3C XML 1.0 encoding requirement](https://www.w3.org/TR/2008/REC-xml-20081126/#charencoding).

Two concrete byte inputs reproduced through the current public Python binding:

```python
b'<?xml version="1.0" encoding="UTF-16"?><root/>'
b'<?xml version="1.0" encoding="US-ASCII"?><root>\xc3\xa9</root>'
```

The first contains single-byte ASCII markup rather than UTF-16 code units or its required BOM. The second contains bytes outside US-ASCII. Both returned `{00000000-0000-4000-8000-000000000000}`, changed complete package bytes, and survived save/reopen verbatim in `customXml/item1.xml`. Expected behavior for these inconsistent representations is `Error::Other`, mapped to Python `RdocxError`, with complete package bytes unchanged before allocation/publication. This retains B4 because it violates the same admission invariant. It does not request namespace validation, DTD support or blanket refusal of ordinary XML declarations.

The pinned quick-xml reader does not supply a declaration-to-byte consistency check. Its `src/reader/state.rs:288` encoding feature branch, when enabled, refines a decoder rather than validating the already globally interpreted input. Application admission still performs raw-byte parsing and the UTF-8 precheck above. Subsequent staging copies supplied bytes unchanged at `crates/rdocx/src/bibliography.rs:1859`, and staged reopen does not refuse the reproduced mismatch.

The native document-event test at `crates/rdocx/tests/integration_test.rs:27677` and Python counterpart at `crates/rdocx-py/tests/test_core.py:6783` cover declaration placement, syntax and attribute adjacency but omit this encoding discriminator. Their passing results do not close this gap. The probe also admitted ordinary declarations and preserved their original bytes, including tab/newline separators, standalone, UTF-8 and a legal trailing PI. No repair was made.
